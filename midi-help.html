MIDI connection help

Mac + Chrome 152: a browser bug can stop device connections. The MIDI port can appear normally and notes may play, while identification, imports and dump captures time out. This also may affect browsers that share Chromium's MIDI backend.

Tested Mac workaround

Download the digi-roll Chrome launcher. Save it in Downloads, then run this in Terminal:

bash ~/Downloads/digi-roll-chrome.command

The launcher opens the hosted lab in Google Chrome with the affected MIDI backend disabled. It uses a separate digi-roll browser profile, so your ordinary Chrome can stay open. Allow MIDI access when prompted. Bookmarks, permissions and saved piano-roll patterns in your usual Chrome profile are separate; they are not copied or deleted. The lab still requires downloading your session ZIP before closing its tab.

Use this launcher each time you start the workaround browser, including after restarting your Mac. A normal Chrome launch does not apply this workaround. For a local lab, pass its address:

bash ~/Downloads/digi-roll-chrome.command http://127.0.0.1:8765/difflab.html

If you prefer your existing Chrome profile: save your work and fully quit Chrome with ⌘Q, then run:

open -a "Google Chrome" --args --disable-features=MidiMacUmp

That command only applies to that launch. Check chrome://version → Command Line for --disable-features=MidiMacUmp. Clearing cache or changing device firmware does not repair this browser bug.

When can I stop using the workaround?

As of September 8, 2026, we reproduced the failure in Chrome 152.0.7977.83 on macOS. Disabling the new backend restored identity replies and checksum-validated A01 dump reads from Digitakt II, Digitone II and Analog Four. Hardware writes were not tested in this browser check. Chromium has an upstream fix for the SysEx framing defect, but we have not verified a fixed shipping Chrome release. Keep Chrome updated; we will name a verified release here after testing. The launch switch is temporary and Chrome may eventually remove it.

Ordinary MIDI playback is not a sufficient test. A replacement browser release needs successful identification and dump reads; writing needs a separate scratch-project check with digi-roll's backup and byte verification still enabled.

If you still cannot connect

  • Wait for the box to finish booting and select the same device you intend to use.
  • Allow MIDI and SysEx access for this site's address. Local and hosted addresses have separate permissions.
  • Check USB/MIDI input and output routing on the box. If it was just plugged in, refresh the device list or reload after saving your work.
  • Record your browser version, macOS version, device name and exact error when reporting a problem.

A timeout alone does not prove this Chrome bug. The app's browser hint never blocks a successful connection or enables writes.
